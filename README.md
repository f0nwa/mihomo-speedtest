# Mihomo-Speedtest

<p align="center">
  <img src="./assets/readme/hero.svg" width="100%" alt="Mihomo-Speedtest: реальные замеры скорости прокси на Keenetic и автоматический быстрый пул">
</p>

Mihomo-Speedtest измеряет реальную скорость прокси на роутерах Keenetic
с XKeen, автоматически обновляет пул быстрых нод и сохраняет историю
результатов. Рабочий Mihomo продолжает обслуживать трафик во время замера.

## Зачем он нужен

Штатный `url-test` выбирает ноду по задержке. Низкий пинг не гарантирует
хорошую пропускную способность: сервер с задержкой 40 мс может загружать
данные медленнее сервера с задержкой 90 мс.

Mihomo-Speedtest проверяет доступность нод и скачивает тестовые данные
через каждую из них. По результатам он собирает `fast.yaml`, который
Mihomo использует как автоматически обновляемый быстрый пул.

## Возможности

- **Настраивать Mihomo.** Мастер `setup.sh` собирает ссылки подписок,
  подбирает User-Agent, предлагает имена провайдеров и применяет конфиг.
  При повторной настройке можно перенести существующие подписки.
- **Измерять реальную скорость.** `speedtest2.sh` скачивает тестовые
  данные через установленное ядро Mihomo и поддерживает те же транспорты.
- **Собирать быстрый пул.** Порог отбора калибруется по скорости прямого
  подключения, а проверенный `fast.yaml` заменяется атомарно.
- **Повторять замеры автоматически.** Установщик настраивает cron;
  по умолчанию проверка проходит раз в три часа. Прогон можно запустить вручную.
- **Показывать результаты в браузере.** Веб-панель хранит историю замеров,
  показывает графики скорости и доступность нод. В ней можно менять
  параметры отбора и запускать новый замер.
- **Обновлять инструменты с роутера.** Есть проверка версий и отдельное
  обновление скриптов и веб-интерфейса через HTTPS.

## Как проходит замер

1. Скрипт читает ноды из настроенных подписок.
2. Отдельный экземпляр Mihomo отсеивает недоступные узлы.
3. Через доступные ноды загружаются тестовые данные.
4. Ноды, прошедшие порог скорости, попадают в новый `fast.yaml`.
5. Результаты сохраняются для графиков и таблицы доступности.

Веб-панель позволяет увидеть результат: какие ноды прошли отбор,
как менялась их скорость и насколько регулярно они были доступны.
После установки она открывается по адресу `http://<IP роутера>:8899/`.

[Алгоритм, параметры отбора и веб-панель](docs/guide.md#speedtest-измеряем-реальную-скорость-а-не-пинг)

## Начало работы

Понадобятся Keenetic с USB-накопителем и Entware, установленный XKeen
с ядром Mihomo, доступ по SSH под root и от одной до трёх подписок
в формате Clash YAML.

| Компонент | Минимальная версия |
|---|---|
| XKeen | 2.0 |
| Mihomo | 1.19.29 |
| KeeneticOS | 5.1.4 |

Установщики проверяют версии и останавливаются, если требования не выполнены.

Самый быстрый способ - одна команда по SSH на роутере:

```sh
curl -fsSL https://raw.githubusercontent.com/f0nwa/mihomo-speedtest/main/install.sh | sh
```

Она сама скачивает и проверяет по SHA256 весь набор файлов проекта (тот
же проверенный релиз на GitHub, что и управляемое обновление ниже), затем
либо запускает мастер настройки `setup.sh` (если `config.yaml` ещё нет),
либо сразу ставит/обновляет спидтест (если конфиг уже настроен).
Подробности - в [руководстве](docs/guide.md#установка-одной-командой).

Без интернета на роутере, либо чтобы перенести конкретную локальную копию
проекта, файлы копируются вручную:

1. Скопируйте файлы проекта на роутер в `/opt/etc/mihomo-speedtest`.
   Для первой установки нужны также `setup.sh`, `config.example.yaml`
   и вспомогательные скрипты, поэтому переносите весь набор файлов проекта.
2. Подключитесь к роутеру по SSH и запустите мастер:

   ```sh
   cd /opt/etc/mihomo-speedtest
   sh setup.sh
   ```

3. Укажите подписки и параметры отбора, дождитесь пробного замера
   и откройте веб-панель статистики.

Если рабочий конфиг уже настроен, для установки замерщика используется
`sh install.sh`. Подробности и команды переноса файлов приведены
в [руководстве](docs/guide.md#установка-с-нуля).

Чтобы полностью убрать надстройку с роутера (веб-службу статистики,
cron-задачу и, если нужно, откат `config.yaml`), используйте
`uninstall.sh` - подробности в [руководстве](docs/guide.md#деинсталляция).
Как и install.sh, он самодостаточен и ставится одной командой:

```sh
curl -fsSL https://raw.githubusercontent.com/f0nwa/mihomo-speedtest/main/uninstall.sh | sh
```

## Ограничения и безопасность

Замеры расходуют трафик и ресурсы роутера; размер загрузки, таймауты
и состав проверяемых нод настраиваются. Скорость зависит от текущего
состояния канала и серверов.

Для веб-интерфейса обязателен Python 3: установщик пытается поставить
его через Entware. Без него CLI и сам speedtest продолжают работать как
обычно, а веб-интерфейс просто не запускается - открытого резерва без
пароля больше нет. Веб-интерфейс работает как отдельная Entware-служба
(`/opt/etc/init.d/S80speedtest-stats`) - поднимается сразу после загрузки
роутера, не дожидаясь первого прогона по cron, и сама перезапускает
упавший HTTP-процесс с нарастающей задержкой. Подробности, команды
start/stop/restart/check и диагностика - в
[руководстве](docs/guide.md#независимая-служба-веб-интерфейса-статистики).

Весь веб-интерфейс и API закрыты входом: при первой установке или
обновлении на роутере печатается одноразовый код и адрес `/setup` для
первичной настройки логина и пароля; сбросить их можно по SSH командой
`sh stats_auth.sh reset`. У сервиса нет HTTPS, поэтому держите его только
в доверенной локальной сети или за отдельным защищённым туннелем (VPN,
проброс порта по SSH) - не открывайте порты `8899` и `9090` в интернет.
Подробности - в
[руководстве](docs/guide.md#обязательная-авторизация-веб-интерфейса).
Рабочий `config.yaml` содержит ссылки подписок и пароли, исключён из Git
и не должен публиковаться.

### Управляемое обновление: CLI

`sh /opt/etc/mihomo-speedtest/update.sh --check` проверяет манифест стабильного релиза.
При росте схемы обновлятор готовит кандидат конфига в RAM, показывает diff
и проверяет его через Mihomo. Применение включает общий откат и один
перезапуск XKeen с проверкой процесса и локального API. См.
[правила подготовки и подтверждения](release/manifest-format.md#кандидат-в-плане-обновления-часть-32).

`--plan --components=web --format=json` показывает выбранный компонент,
зависимости, точный тег, файлы и влияние на службы.

`--prepare --components=web --format=json` запускает проверенный свежий
обновлятор из /tmp и сохраняет подготовленный набор с идентификатором plan_id.
`--verify-plan <plan_id>` повторно проверяет релиз, локальные файлы и набор;
для локальных правок нужен `--confirm-local`. `--discard-plan <plan_id>`
удаляет подготовленный набор. План действует 24 часа и исчезает при перезагрузке.

Подготовка не пишет в /opt. `--apply <plan_id>` повторно проверяет план и
применяет его с откатом при ошибке; для локальных правок нужен --confirm-local.
`--rollback-last` восстанавливает предыдущее состояние, `--recover` восстанавливает
прерванную операцию. Эти две команды не требуют сети. Незавершённый журнал
блокирует новый план. Для загрузки нужны curl, сертификаты и опубликованный публичный
HTTPS-релиз. Формат, ограничения и ручное обновление bootstrap описаны
в [спецификации манифеста](release/manifest-format.md).

Первый публичный комплект обновлений: [релиз v1](https://github.com/f0nwa/mihomo-speedtest/releases/tag/v1).

### Управляемое обновление: веб-интерфейс

Поверх CLI выше в веб-интерфейсе есть раздел «Обновления» (вкладка
`/updates`, пассивный бейдж на `/stats` и `/settings`). Кнопка «Проверить
сейчас» запускает лёгкую проверку манифеста (без скачивания файлов
релиза) и обновляет бейдж и список изменений. Кнопка «Обновить» сначала
открывает экран подтверждения с diff (что изменится, нужна ли миграция
конфига) и только после подтверждения запускает применение в фоне с
индикацией прогресса. Ежедневная фоновая проверка (по умолчанию 5:17,
cron-строка ставится `install.sh`) работает так же, как «Проверить
сейчас», и никогда сама не применяет обновление - применение всегда
требует явного нажатия «Обновить» человеком. Состояние проверки и
текущей фоновой операции хранится в `/tmp/mihomo-speedtest-update` и, как
и остальной рабочий кэш проекта, не переживает перезагрузку роутера -
после неё бейдж пуст до следующей проверки. Подробности - в
[руководстве](docs/guide.md#раздел-обновления-в-веб-интерфейсе).
