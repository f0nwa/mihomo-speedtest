# Файловый менеджер в веб-панели - дизайн

## Цель
Вкладка «Файлы» в веб-панели: просмотр каталогов, загрузка и скачивание
файлов, правка текстовых файлов (конфиги .yaml/.json/.sh). Одинаково на
mipsel и aarch64: только python3 stdlib, без бинарей и новых зависимостей.
Доступ - под существующей сессией панели. Файловая система открыта **от
корня `/`** (решение владельца), интерфейс - вариант B из макетов: дерево
слева, список по центру, редактор справа.

## Не входит (YAGNI)
Архивы, chmod/chown, поиск, массовые операции, ссылки для шаринга.

## Серверная часть
- `web/stats_files.py` - чистые функции без HTTP (тестируются отдельно, как
  `stats_auth.py`). `stats_httpd.py` только маршрутизирует `/api/fm/*`.
- Единственный корень - `/`. Пути в API абсолютные (`/opt/etc/mihomo/config.yaml`).
  Белого списка каталогов нет, поэтому безопасность держится на других мерах:
  - нормализация пути (`normpath`, абсолютный путь обязателен, нулевой байт -
    отказ); симлинки разрешены, `lstat` показывает их как ссылки со ссылкой;
  - `read`/`download` только для обычных файлов (S_ISREG): устройства, сокеты,
    FIFO и содержимое `/proc`, `/sys`, `/dev` не читаются как файлы (в списке
    они помечены и без размера), чтобы не повесить процесс на бесконечном потоке;
  - защищённые пути (`/`, `/bin`, `/sbin`, `/lib`, `/etc`, `/opt`, `/proc`,
    `/sys`, `/dev`, точки монтирования): удалить, переименовать или перенести
    нельзя, содержимое внутри них - можно;
  - `recursive`-удаление только с явным подтверждением в UI и полем
    `confirm=<путь>` в запросе;
  - файлы самой панели (`$DIR/stats_auth*`, файл хэша пароля и сессий) открываются
    только на чтение: правка из веб-интерфейса отключена, чтобы не потерять вход.
- Эндпоинты (JSON, нужна сессия):
  - `GET /api/fm/tree?path=` - только подкаталоги, для ленивого дерева
  - `GET /api/fm/list?path=` - имя, тип, размер, mtime, права; лимит записей
  - `GET /api/fm/download?path=` - потоком, `Content-Disposition`
  - `GET /api/fm/read?path=` - текст до 1 МиБ; бинарные/большие - отказ
  - `PUT /api/fm/write` - временный файл рядом, fsync, rename; прежнее
    содержимое в `.bak`; опциональный `mtime` для обнаружения конфликта
  - `POST /api/fm/upload?path=&name=` - потоком блоками 64 КиБ в `*.part`,
    затем rename; общий лимит размера, проверка места через `statvfs`
  - `POST /api/fm/mkdir`, `/rename`, `/delete` (непустой каталог - только с
    `recursive` и `confirm`; защищённые пути - отказ)
- Защита: CSRF-заголовок на все изменяющие запросы, rate-limit на
  загрузку/удаление, журнал изменяющих операций в живом журнале панели, `.bak` и `.part` скрыты в списке по умолчанию.
- Ресурсы (mipsel): всё потоковое, список и чтение ограничены лимитами;
  fork на соединение уже есть, параллельные загрузки панель не блокируют.

## Интерфейс (вариант B)
`web/stats_app_files.js`, вкладка «Файлы», три колонки:
- слева дерево от `/` (подкаталоги подгружаются при раскрытии);
- по центру список текущего каталога: хлебные крошки, «Загрузить / Папка / Файл»,
  зона перетаскивания (XHR с прогрессом), сортировка;
- справа редактор на CodeMirror: «Сохранить», «Скачать», «Переименовать»,
  «Удалить». Бинарные и большие файлы не открываются, а предлагают скачать.
Удаление и правка вне рабочих каталогов проекта требуют подтверждения; на
телефоне колонки превращаются в экраны (дерево -> список -> редактор).

## Установка и сопровождение
Новые файлы добавляются в `release/components.txt`, `install.sh`,
`uninstall.sh` по образцу остальных веб-файлов (их подхватывает и обновлятор).
Документация: раздел в `docs/guide.md`, строка в README.

## Тесты (`tests/test_stats_files*.sh`)
Нормализация пути (`..`, относительные, нулевой байт), симлинки, чтение только
обычных файлов (устройства, FIFO, /proc), обрыв загрузки (не
остаётся `.part`), атомарность записи, конфликт по mtime, отказ без CSRF,
лимиты размера и числа записей, защищённые пути, `recursive` без `confirm`, файлы панели только на чтение.
